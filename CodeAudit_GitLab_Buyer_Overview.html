CodeAudit One   /   Evidence before permission
Technology acquisition overview

When code is abundant,
verification becomes the bottleneck.

A bounded, independent verification capability for determining whether a specific proposed code change satisfies its required obligations before a protected GitHub merge.

A generated fix is not the same thing as a qualified fix.

What is working today

In a real private GitHub pilot, the CodeAudit App passed a qualifying revision and prevented a deliberately defective revision using its required protected check. A separate executable replay produced a concrete authorization counterexample and rechecked a bounded repair while retaining required functionality.

PASSQualifying revision, exact App-owned GitHub required check on PR #7
BLOCKEDDeliberate regression, App-owned required check prevented merge on PR #8
REPLAYExecutable witness and independently rechecked bounded repair in separate local acceptance tests

Why it could matter to GitLab

GitLab already invests in detecting vulnerabilities and producing repairs. CodeAudit addresses a different question: whether the resulting exact revision has enough independently checked evidence to proceed. This may complement GitLab's Governed Software Factory by placing a testable qualification boundary between change generation and merge.

Falsifiable, deliberately bounded

The verified engine supports a defined finite TypeScript scope. These results do not establish universal software correctness, buyer-tested superiority over GitLab, or a generally available cloud proof service. The acquisition case is faster progress toward rigorous change qualification, subject to an independent evaluation.
